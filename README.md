# gl00m's dotfiles

NixOS + Home Manager + Hyprland for an ASUS Zenbook Duo UX8406CA.

This repo is intended to be the reproducible machine layer: system packages, desktop shell, user configs, agent configs, and service wiring live here. Personal state does not. Browser profiles, SSH keys, agent memories, caches, and decrypted secrets stay outside the repo.

Most day-to-day changes are applied with:

```bash
nixrebuild
```

## Start Here: Installing Things

You do not usually need to think about flakes.

- Normal GUI apps and CLI tools: add them to `modules/apps.nix`, then run `nixrebuild`.
- System services, drivers, users, boot, hardware, and Steam itself: edit `configuration.nix`, then run `nixrebuild`.
- Shell aliases/functions/prompt tools: edit `modules/shell.nix`, then run `nixrebuild`.
- Hyprland keybinds/monitor/window rules: edit `config/hypr/hyprland.conf`, then run `hyprctl reload` or `nixrebuild`.
- Steam games: install them inside Steam like on Windows. They are not Nix packages and do not go in any `.nix` file.
- Random AppImages from the web: either run `appimage-run ./Thing.AppImage` or install one with `appimage-install ./Thing.AppImage`.

Flakes are only the pinned build backend. Day to day, treat this repo as:

```text
configuration.nix   # system/hardware/services
home.nix            # Home Manager entrypoint, mostly imports modules
modules/apps.nix    # normal apps: edit this most often
modules/*.nix       # focused user config modules
config/*            # raw app/desktop config files
```

Raw equivalent of `nixrebuild`:

```bash
sudo nixos-rebuild switch --flake .#gl00m-full
```

## Build Targets

| Target | Command | Scope |
|--------|---------|-------|
| Full machine | `make full` | NixOS + Home Manager via `.#gl00m-full` |
| System only | `make system` | NixOS via `.#nixos` |
| User only | `make user` | Home Manager via `.#gl00m` |
| Update inputs | `make update` | Updates `flake.lock` |
| Clean store | `make clean` | Runs `nix-collect-garbage -d` |

Preferred daily command:

```bash
nixrebuild
```

`nixrebuild` is defined in `modules/shell.nix`. It stages changes, optionally commits, dry-activates, and only applies the rebuild if the dry run passes.

```bash
nixrebuild           # full rebuild
nixrebuild -system   # system only
nixrebuild -user     # Home Manager only
```

Important flake detail: new files must be tracked by git before Nix can see them. If a build says a path is not tracked, run:

```bash
git add <path>
```

## Fresh Install

These steps assume NixOS is already installed and this repo is cloned to `~/dotfiles`.

1. Make sure flakes are enabled:

   ```bash
   sudo nix --extra-experimental-features "nix-command flakes" flake show ~/dotfiles
   ```

2. Create or import your SSH key:

   ```bash
   mkdir -p ~/.ssh
   chmod 700 ~/.ssh
   ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519 -C "$USER@$(hostname)"
   ```

   Skip key generation if you already have `~/.ssh/id_ed25519`.

3. Create the local SOPS age identity file outside dotfiles:

   ```bash
   mkdir -p ~/.config/sops/age
   chmod 700 ~/.config/sops/age
   nix run nixpkgs#ssh-to-age -- -private-key -i ~/.ssh/id_ed25519 -o ~/.config/sops/age/keys.txt
   chmod 600 ~/.config/sops/age/keys.txt
   ```

4. If this is a different machine/user, update the SOPS recipient:

   ```bash
   nix run nixpkgs#ssh-to-age -- -i ~/.ssh/id_ed25519.pub
   ```

   Put the printed `age1...` recipient in `.sops.yaml`, replacing the existing recipient. Then recreate the encrypted Hermes secret:

   ```bash
   printf "openai_api_key: replace-me\n" > /tmp/hermes.yaml
   nix run nixpkgs#sops -- --config .sops.yaml --filename-override secrets/hermes.yaml --encrypt /tmp/hermes.yaml > secrets/hermes.yaml
   rm /tmp/hermes.yaml
   ```

5. Add your OpenAI API key:

   ```bash
   sops secrets/hermes.yaml
   ```

   Set:

   ```yaml
   openai_api_key: your_real_openai_key_here
   ```

   Do not put API keys in `.env` files, shell rc files, `configuration.nix`, or chat logs.

6. Apply the full system:

   ```bash
   cd ~/dotfiles
   sudo nixos-rebuild switch --flake .#gl00m-full
   ```

7. Log out and back in once after the first Home Manager activation so session variables, fonts, desktop entries, and shell integration are fully loaded.

## Secrets

Secrets use SOPS with age. The encrypted file is committed:

```text
secrets/hermes.yaml
```

The local private identity is not committed:

```text
~/.config/sops/age/keys.txt
```

Home Manager exports this for interactive shells:

```bash
SOPS_AGE_KEY_FILE="$HOME/.config/sops/age/keys.txt"
```

If `sops secrets/hermes.yaml` cannot decrypt, check:

```bash
ls -l ~/.config/sops/age/keys.txt
echo "$SOPS_AGE_KEY_FILE"
source ~/.nix-profile/etc/profile.d/hm-session-vars.sh
```

Then retry:

```bash
sops secrets/hermes.yaml
```

```text

```

Managed symlinks:

| Runtime path | Source |
|--------------|--------|
| `~/.codex/config.toml` | `agents/codex/config.toml` |
| `~/.codex/rules/default.rules` | `agents/codex/rules/default.rules` |
| `~/.claude/settings.json` | `agents/claude/settings.json` |
| `~/.claude/CLAUDE.md` | `agents/claude/CLAUDE.md` |
| `~/.config/tmux/tmux.conf` | `agents/tmux/tmux.conf` |

If one of these files already exists and is not a symlink, Home Manager moves it aside as `*.hm-backup` before linking the managed version.

## Hermes

Hermes is configured as a NixOS service. It does not receive the OpenAI API key in its environment.

Flow:

```text
Hermes -> http://127.0.0.1:11435/v1 -> openai-proxy -> https://api.openai.com/v1
```

The proxy runs as the restricted `openai-proxy` system user and reads the decrypted SOPS secret from `/run/secrets/...`. Hermes only sees a local OpenAI-compatible base URL.

Relevant files:

| File | Purpose |
|------|---------|
| `agents/hermes/config.yaml` | Hermes model/tool/memory config |
| `agents/hermes/USER.md` | Hermes context document |
| `agents/openai-proxy/openai-proxy.py` | Local key-injecting OpenAI proxy |
| `modules/agent-services.nix` | SOPS secret, proxy service, Hermes service wiring |
| `secrets/hermes.yaml` | Encrypted OpenAI key |

After editing the API key or Hermes service config:

```bash
nixrebuild
```

Check status:

```bash
systemctl status openai-proxy
systemctl status hermes-agent
```

Check that Hermes is pointed at the local proxy and does not expose the key:

```bash
systemctl cat hermes-agent | rg "11435|OPENAI|Environment"
systemctl cat openai-proxy | rg "11435|key-file|User="
```

Expected:

- `hermes-agent` references `127.0.0.1:11435`.
- `hermes-agent` does not contain `OPENAI_API_KEY`.
- `openai-proxy` runs as `User=openai-proxy`.

## tmux

tmux is installed by Home Manager and configured at:

```text
agents/tmux/tmux.conf
```

Interactive Bash shells auto-attach to session `main`:

```bash
tmux new-session -A -s main
```

VS Code terminals are skipped. To bypass tmux for one shell:

```bash
NO_TMUX=1 bash
```

Current tmux basics:

| Key | Action |
|-----|--------|
| `Ctrl-a` | Prefix |
| `Ctrl-a` then `|` | Split horizontally |
| `Ctrl-a` then `-` | Split vertically |
| `Ctrl-a` then `c` | New window in current path |
| `Ctrl-a` then `r` | Reload tmux config |

## Hardware Notes

Target machine:

```text
ASUS Zenbook Duo UX8406CA
Intel Core Ultra 9
Dual 2880x1800 120Hz OLED screens
```

Display notes:

- `eDP-1` is the main display.
- `eDP-2` is the lower ScreenPad Plus display.
- `eDP-2` is currently disabled in `config/hypr/hyprland.conf` until workspace routing is planned.

Backlight notes:

- `intel_backlight` is the correct main display backlight.
- `card1-eDP-2-backlight` exists but belongs to the disabled lower display.
- `asus::kbd_backlight` is not currently exposed in `/sys/class/leds/` on this machine, so keyboard backlight software control gracefully notifies instead of failing silently.

ASUS service notes:

- `asusd` and `supergfxd` are enabled.
- `/etc/asusd` is created through `systemd.tmpfiles.rules` because `asusd` expects it.

## What Not To Commit

Do not commit:

- Plaintext API keys
- `~/.config/sops/age/keys.txt`
- SSH private keys
- Browser profiles
- Agent memory/cache/state
- `result` build symlinks
- Large personal downloads

The repo should be safe to share as a reproducible config base. Personal identity, secrets, and long-term agent memory belong in separate private storage.
