# gl00m's dotfiles

NixOS + Hyprland on an ASUS Zenbook Duo UX8406CA. One repo, one command to rebuild the whole machine.

```
sudo nixos-rebuild switch --flake .#gl00m-full
```

---

## Hardware

**ASUS Zenbook Duo UX8406CA** — Intel Core Ultra 9, dual 2880×1800 @ 120Hz OLED screens.

- `eDP-1` — main display, always on
- `eDP-2` — ScreenPad Plus (secondary screen below keyboard), currently disabled in hyprland.conf; needs workspace routing plan before re-enabling
- Keyboard sends F1–F6 keysyms by default (Fn Lock active) — both F-key and XF86 binds exist in hyprland.conf
- Backlight: `intel_backlight` is the correct device; `card1-eDP-2-backlight` also exists but writes to the disabled screen. A udev rule scopes backlight group access to `intel_backlight` only.
- `asus::kbd_backlight` does not exist in `/sys/class/leds/` on this model — keyboard backlight software control not yet available; shows a mako notification on keypress instead of silently failing
- ASUS services (`asusd`) require `/etc/asusd/` to exist — created via `systemd.tmpfiles.rules`

## Build targets

| Target | Command | Scope |
|--------|---------|-------|
| `gl00m-full` | `make full` | System + home-manager — use this one |
| `nixos` | `make system` | System only (`configuration.nix`) |
| `gl00m` | `make user` | Home-manager only, no sudo, faster |

`make update` bumps all flake inputs and regenerates `flake.lock`. Review the diff before applying.

## nixrebuild

`nixrebuild` is a shell function in `modules/shell.nix`. It wraps the rebuild with git integration:

```
nixrebuild           # full rebuild (gl00m-full)
nixrebuild -system   # configuration.nix only
nixrebuild -user     # home.nix only, no sudo
```

Order of operations:
1. `git add .` — stages everything
2. Prompts for a commit message (blank = skip commit)
3. Commits if message provided
4. Runs `nixos-rebuild dry-activate` — builds without applying; catches broken expressions
5. If dry-activate fails: `git reset --soft HEAD~1` rolls back the commit, changes stay staged
6. If dry-activate passes: pushes to remote, then applies the rebuild

Committing before dry-run keeps the flake evaluation tree clean (no "dirty git tree" warnings from Nix).

## How config files reach ~/.config/

Home-manager symlinks files from the repo into `~/.config/` on every rebuild. Editing `~/.config/hypr/hyprland.conf` directly does nothing — it's a read-only symlink. All changes go through the repo.

```nix
# plain file
home.file.".config/hypr/hyprland.conf".source = ../config/hypr/hyprland.conf;

# executable script
home.file.".config/hypr/brightness.sh" = {
  source = ../config/hypr/scripts/brightness.sh;
  executable = true;
};
```

Scripts are sourced from `config/hypr/scripts/` but symlinked into `~/.config/hypr/` so hyprland.conf binds (`~/.config/hypr/brightness.sh`) keep working.

## Flake inputs

| Input | Purpose |
|-------|---------|
| `nixpkgs` | Package set |
| `home-manager` | User environment management |
| `hermes-agent` | NousResearch Hermes AI agent (NixOS module) |
| `zen-browser` | Zen Browser (not in nixpkgs; standalone flake) |
| `caelestia` | Desktop shell — fetched from `github:gl00mt1t4n/caelestia-shell` |

`nixpkgs.legacyPackages` does not support overlays — `pkgs` is constructed manually via `import nixpkgs { inherit system; overlays = [...]; }`.

The `caelestia` package is overridden in `flake.nix` to load QML files from `/home/gl00m/dotfiles/caelestia` (the local submodule) instead of the Nix store. This means any edit to a `.qml` file hot-reloads instantly without running `make user`. C++ plugin changes require pushing to the fork, running `make update`, then `make user`.

## Caelestia shell

The desktop shell is [caelestia-dots/shell](https://github.com/caelestia-dots/shell) (fork at `gl00mt1t4n/caelestia-shell`), built with QuickShell + Qt6. It replaces waybar (bar), mako (notifications), and swayosd (OSD).

**Customization:**
| Change | How |
|--------|-----|
| Layout, components, theme | Edit `caelestia/**/*.qml` → QuickShell hot-reloads instantly |
| Shell settings (fonts, spacing, transparency) | Edit `config/caelestia/shell.json` → `systemctl --user restart caelestia` |
| Per-monitor overrides | `config/caelestia/monitors/<screen-name>/shell.json` |
| Advanced design tokens | `config/caelestia/shell-tokens.json` |
| C++ plugin (new backend features) | Edit `caelestia/plugin/src/...` → `make user` |

**Pushing changes to the fork:**
```bash
cd ~/dotfiles/caelestia
git add .
git commit -m "describe change"
git push

# then update the submodule ref in the parent repo
cd ~/dotfiles
git add caelestia
git commit -m "update caelestia submodule"
```

## Fresh install

1. Clone repo
2. `git submodule update --init` — populates the `caelestia/` submodule
3. `sudo nixos-rebuild switch --flake .#gl00m-full`
4. Create Hermes API key (not in repo):
   ```bash
   sudo mkdir -p /var/lib/hermes
   echo 'OPENROUTER_API_KEY=your-key' | sudo tee /var/lib/hermes/env
   sudo chmod 600 /var/lib/hermes/env
   ```
5. Add a wallpaper: place image anywhere, edit `config/hypr/hyprpaper.conf` with the path

Not tracked by Nix (must recreate manually after fresh install):
- `/var/lib/hermes/env` — API key
- `~/.ssh/` — SSH keys
- `~/.gnupg/` — GPG keys
- Browser profiles, bookmarks, downloads
